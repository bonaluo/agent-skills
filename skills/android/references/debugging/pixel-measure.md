# 像素量测

从截图里量出精确到像素的尺寸。有两档手段：**裁切放大目视** 和 **导出原始像素值核对**。

## 裁切放大

已知大概位置时最快：

```bash
ffmpeg -y -i shot.png -vf "crop=90:200:990:1370,scale=270:600:flags=neighbor" zoom.png
#                               宽 高  x   y        放大倍数       最近邻，避免插值模糊
```

**`crop` 的参数顺序是 `宽:高:x:y`，不是 `x:y:宽:高`**，很容易记反。

`scale=W:H` 里 W/H 是**目标尺寸**，不是倍数。`crop=90:200` 配 `scale=270:600`
就是横竖各放大 3 倍。只想横向放大时写 `scale=270:200`。

放大用 `flags=neighbor`，双线性插值会把边缘糊掉，量不准。

## 导出原始像素值

需要精确到像素时，把区域导成原始灰度（或 RGB）字节流再逐个数：

```bash
# 一整行：y=660，x 从 1005 起 70 个像素
ffmpeg -v error -i shot.png -vf "crop=70:1:1005:660" -pix_fmt gray -f rawvideo - | od -An -tu1 -v -w70

# 一整列：x=1036，y 从 1380 起 180 个像素
ffmpeg -v error -i shot.png -vf "crop=1:180:1036:1380" -pix_fmt gray -f rawvideo - | od -An -tu1 -v -w30

# 单个像素的 RGB
ffmpeg -v error -i shot.png -vf "crop=1:1:1041:700" -pix_fmt rgb24 -f rawvideo - | od -An -tu1
```

`od` 的 `-wN` 表示每行打印 N 个字节，**把 N 设成等于裁切宽度**，
输出就自然变成"每行 = 裁切区域的一行"，便于对照坐标。

`crop=W:1:X:Y` 是取一行，`crop=1:H:X:Y` 是取一列，别和 `crop=1:1` 取单点混淆。

## 怎么判读

一维输出的每一列就对应一个像素坐标（列号 = 起始坐标 + 序号，序号从 0 开始）。

找边界的方法：数值**突然跳变的那一列**就是边界。例如一行里
`... 244 248 150 154 160 ... 162 166 233 241 ...`，
从 248 掉到 150 的那一列是物体左边缘，从 166 跳回 233 的那一列之后是右边缘。

```
宽度 = 右边缘坐标 - 左边缘坐标 + 1
```

再除以 `density / 160` 换算成 dp，就能和代码里的字面量对上。

## 两个坑

### 1. 低对比度时扫不出来

**白色物体压在浅色背景上**，灰度值可能只差 10 以内（254 vs 245），
逐像素扫描和目视都分不出边界。对策：
- 改用它的**阴影**来定位（阴影通常比背景暗 20~40）；
- 或者干脆换一帧——滚动一点，让物体压到深色内容上再截。

像素扫描不是万能的，量不出来就承认量不出来，别硬凑一个数。

### 2. 量之前确认画面是静止的

异步加载的内容（缩略图、网络图片、动画）会让同一位置两次取值不同，
量出来的"边界"其实是噪声。截两张对比，画面一致了再量。

同理，**不要拿"这一帧"当"稳态"**——如果界面还在进入动画中，
量到的尺寸就是中间态。
