# MyBatis ORM 最佳实践

## 核心原则

1. **约定优于配置**：遵循 MyBatis 和 Spring Boot 的默认约定，减少不必要的配置
2. **单一职责**：每个 Mapper 接口只负责一个实体的数据操作
3. **安全性优先**：防止 SQL 注入，使用预编译语句
4. **可维护性**：保持代码清晰，易于理解和修改

## 项目结构

### 目录组织
```
src/main/java/
└── com/example/
    └── mapper/          # Mapper 接口
    └── entity/          # 实体类
    └── dto/             # 数据传输对象

src/main/resources/
└── mapper/              # MyBatis XML 映射文件
```

### 文件命名规范
- Mapper 接口：`XxxMapper.java`（使用驼峰命名）
- XML 映射文件：`XxxMapper.xml`（与接口同名）
- 实体类：`Xxx.java`
- DTO：`XxxDTO.java` 或 `XxxVO.java`

## Mapper 设计

### 接口定义
- 使用 `@Mapper` 注解标注接口
- 方法命名清晰表达操作意图（如 `findById`、`findByUsername`）
- 返回类型明确（单个对象、列表、基本类型）
- 避免在接口中写复杂业务逻辑

### XML 映射文件
- 存放在 `resources/mapper/` 目录
- 使用 `resultMap` 统一映射关系，避免重复
- 开启驼峰命名转换（`map-underscore-to-camel-case`）
- SQL 语句保持简洁，复杂查询考虑拆分

## 查询优化

### 索引使用
- WHERE 条件字段建立索引
- 避免在索引字段上使用函数
- 合理使用联合索引

### 分页查询
- 大数据量查询必须使用分页
- 避免 `SELECT *`，只查询需要的字段
- 使用 `LIMIT` 和 `OFFSET` 时注意性能

### 缓存策略
- 合理使用一级缓存（SqlSession 级别）
- 根据业务需求配置二级缓存
- 注意缓存一致性问题，及时清除缓存

## 事务管理

### 事务边界
- 在 Service 层使用 `@Transactional` 管理事务
- 避免在 Mapper 层处理事务
- 选择合适的事务传播行为

### 批量操作
- 批量插入使用 `SqlSession` 的批量模式
- 注意批量操作的事务大小，避免内存溢出
- 大批量数据考虑分批提交

## 安全性

### 防止 SQL 注入
- 使用 `#{}` 而非 `${}`（除非必要）
- 对用户输入进行验证和转义
- 避免动态拼接 SQL

### 敏感信息
- 数据库密码使用环境变量配置
- 生产环境配置连接池参数
- 启用 SSL 连接（生产环境）

## 代码生成

### 使用 MyBatis Generator
- 自动生成实体类、Mapper 接口和 XML
- 自定义模板适应项目规范
- 保留手动修改区域避免覆盖

### Lombok 集成
- 实体类使用 `@Data` 简化代码
- 避免过度使用，保持代码可读性

## 测试建议

### 单元测试
- 测试 Mapper 接口的方法
- 使用 H2 内存数据库进行集成测试
- 验证 SQL 语句的正确性

### 性能测试
- 监控慢查询
- 使用 MyBatis 日志查看实际执行的 SQL
- 定期分析数据库性能

## 常见问题处理

### N+1 查询问题
- 使用 `JOIN` 或批量查询避免
- 合理使用延迟加载

### 字段映射问题
- 注意数据库字段名和 Java 属性名的映射
- 使用 `@Results` 或 XML 中的 `resultMap` 明确映射

### 主键生成
- 使用数据库自增主键
- 分布式系统考虑雪花算法等全局唯一 ID
