# 文档总结技能

## 核心工作流程

### 步骤一：获取文档内容

根据输入类型获取纯文本内容：

| 输入类型 | 处理方式 |
|---------|---------|
| 粘贴的纯文本 | 直接使用 |
| 文件路径 | 读取文件内容（支持 .txt, .md, .json, .xml, .csv 等纯文本格式） |
| URL | 使用 WebFetch 获取网页文本内容 |
| 图片路径 | 使用 OCR 能力提取图片中的文字 |

**重要**：仅处理纯文本格式。PDF、Word 等二进制格式请先转换或跳过。

### 步骤二：分析知识领域

在开始总结之前，必须先分析文档所属的知识领域。这作为背景信息帮助更好地理解内容深度和术语。

**分类体系**（2-3级）：

```
基础领域层级（选择最匹配的大类）：
├── 哲学与宗教
├── 社会科学（经济学、社会学、法学、政治学等）
├── 文学与艺术（文学评论、艺术理论、语言学等）
├── 历史与地理
├── 自然科学（物理学、化学、生物学等）
├── 工程技术（各工程学科）
├── 医学与健康
├── 农业科学
├── 计算机科学与技术
│   ├── 软件工程
│   ├── 人工智能
│   │   ├── 机器学习
│   │   ├── 深度学习
│   │   ├── 自然语言处理
│   │   └── 计算机视觉
│   ├── 数据库
│   ├── 网络与安全
│   └── 嵌入式系统
├── 教育学
├── 商业与管理
├── 军事科学
└── 其他/跨学科
```

**分析要求**：
- 选择最匹配的1-3级分类路径
- 考虑文档的实际内容和目的，而非仅看表面词汇
- 如果文档涉及多个领域，选择最主要的一个

**调试输出**（仅在分析过程中，输出给用户查看）：
```
[领域分析] 文档属于：计算机科学与技术 → 人工智能 → 自然语言处理
```

### 步骤三：询问详细程度

在开始总结之前，询问用户希望的详细程度：

```
请选择总结的详细程度：
1. 简短摘要（1-3句话）
2. 标准摘要（段落形式，涵盖主要观点）
3. 详细总结（包含要点列表和关键细节）
4. 结构化总结（带层级标题的完整分析）
```

如果用户未明确指定，默认使用"标准摘要"。

### 步骤四：生成总结

根据选择的详细程度生成总结，确保：

- **语言一致**：使用与原文相同的语言（中文文档用中文总结）
- **忠实原文**：准确反映原文意图，不过度解读
- **结构清晰**：使用 Markdown 格式，层次分明
- **保留关键**：不遗漏重要的数据、观点、结论

**总结结构模板**：

```markdown
# 文档总结

## 核心要点
（3-5个最重要的观点或结论）

## 详细内容
（根据详细程度选择展开的层级）

## 关键信息
- **主题**：xxx
- **作者/来源**：xxx（如果有）
- **发表时间**：xxx（如果有）

## 关键词
（5-10个关键词，用逗号分隔）
```

### 步骤五：条件性生成结构图

仅当文档包含以下特征时，才生成结构图/思维导图：
- 层级分明的章节结构（3层以上）
- 多个人物/事件/概念的关系网络
- 流程图或步骤序列
- 时间线或发展脉络

如果文档结构简单（如单段落、无层级），跳过此步骤。

## 输入格式支持

### 纯文本直接使用
用户直接粘贴的文本，直接处理。

### 文件路径
支持的文件格式：`.txt`, `.md`, `.json`, `.xml`, `.csv`, `.log`, `.html`, `.py`, `.js`, `.java`, `.c`, `.cpp`, `.go`, `.rs`, `.sh` 等纯文本代码和文档格式。

读取后取纯文本内容，去除不必要的标记。

### URL
使用 WebFetch 工具获取网页内容，提取正文文本。

### 图片
对于图片文件（如截图、扫描件），使用 OCR 能力提取文字后再处理。

---

## 特殊场景处理

### 多文档合并总结
如果用户提供多个文档（文件列表、多个URL等），默认进行合并总结：

1. 分别为每个文档提取关键信息
2. 识别文档间的关联和差异
3. 生成统一的综合总结
4. 标注不同文档各自的贡献

### 用户指定领域
如果用户在任务中明确指定了领域（如"从AI领域专家的角度总结"），优先使用用户指定的领域背景，而非自动推断。

### 长文档处理
对于超长文档（如超过10万字）：

1. 识别并分段处理
2. 先总结各部分
3. 再综合生成整体总结
4. 标注文档结构和各部分关系

## 输出示例

### 示例1：简短摘要
```
**摘要**：本文介绍了 Transformer 架构的核心机制——注意力机制，解释了为何它比传统 RNN 更适合处理长序列数据，以及它在自然语言处理领域的广泛应用。
```

### 示例2：详细总结

```markdown
# 文档总结：Attention Is All You Need

## 核心要点
1. Transformer 完全基于注意力机制，摒弃了传统的 RNN 和 CNN 结构
2. 自注意力机制允许序列任意位置直接交互，解决了长距离依赖问题
3. 多头注意力从不同角度捕捉信息，提升了模型表达能力

## 详细内容
### 背景
传统的序列建模依赖 RNN，但其固有的顺序计算限制了并行化能力...

### 核心创新
论文提出了自注意力机制，通过查询-键-值三元组计算...

## 关键信息
- **来源**：NeurIPS 2017
- **作者**：Google Brain / Research
- **引用数**：80,000+（截至2023年）

## 关键词
Transformer, Attention Mechanism, Self-Attention, Neural Machine Translation, Sequence Modeling
```

## 注意事项

- **不要捏造**：如果文档中未明确提到，不要添加假设内容
- **保留专业术语**：对于领域特定的术语，保留原文或提供简短解释
- **避免偏见**：客观呈现原文内容，不加入个人立场
- **长度控制**：总结长度通常为原文的 5%-20%，除非用户要求更详细
